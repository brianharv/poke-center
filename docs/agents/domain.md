# Domain docs

This repo uses a single-context layout:

- `GLOSSARY.md` at the repo root.
- Architecture decisions under `docs/adr/`.

Before exploring, read the glossary and ADRs relevant to the work.
If these files are absent, proceed silently; create them through
domain-modeling when terms or decisions are resolved.

Use the glossary's terms when naming domain concepts. Reconsider
unrecognized terminology or note a real gap for domain-modeling.

Surface conflicts with existing ADRs explicitly, identifying the ADR
and explaining why the decision should be revisited.
